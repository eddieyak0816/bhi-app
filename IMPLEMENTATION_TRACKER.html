Built 2026-04-07. Root cause: supabase.auth.getSession() called from AuthContext useEffect on mount deadlocked the Supabase JS auth client when a SIGNED_IN event was already in-flight, leaving user=null and silently blocking all Supabase queries (RLS rejects unauthenticated requests). Fix: AuthContext.tsx now reads JWT from localStorage via getStoredJwt(), decodes user id/email from JWT payload directly, calls supabase.auth.setSession() to hydrate the client's internal session (required for insert/update/delete RLS), then fetches profile via plain fetch with Authorization header. getStoredSession() helper added to supabase.ts.
