11
AI lab PDF upload & extraction (preferred verification method)
User uploads a lab PDF → server extracts text via pdf-parse → AI parses lab values → user reviews in a table → confirmed results saved to app. AI provider cascade: Gemini (up to 5 keys, auto-rotates on 429) → OpenRouter (3 free models) → Groq. Fuzzy marker name matching links extracted values to known app markers for BHAS scoring. Reference range priority: PDF → app optimal logic rule → lab_markers fallback. "Upload Lab PDF" button on Labs page. Extraction accuracy hardened: value_str field prevents digit truncation; </> qualifiers preserved; concatenated-column prompt with Labcorp-format examples; zero-value rows included; unit-boundary truncation fix. PHI rule: patient PDFs excluded from git via .gitignore.
✅ Built
11a
PDF duplicate detection — hash + accession number + collection date
SHA-256 hash checked before extraction (exact file re-upload). Accession number + collection date extracted by AI and checked after extraction (same lab report, different scan). Both checks scope to the current user. lab_pdf_uploads table stores hash, accession_num, collection_date, filename, uploaded_at with RLS. Amber warning banner shown above review table; user can still save results if intentional. Migration: 20260313_create_lab_pdf_uploads.sql.
✅ Built
11b
New Marker Wizard in Admin — guided marker + logic rules creation
3-step guided modal on the Lab Markers tab. Step 1: name + unit (duplicate-checked). Step 2: up to 3 scoring rule rows (Optimal / Improvement / Out of Range) with auto-suggested tag names. Step 3: review summary + single "Create All" button. Server: POST /api/admin/new-marker-wizard creates marker → tags → logic rules atomically. Developer note shown in Step 3 to manually add tags to OPTIMAL_TAGS / IMPROVEMENT_TAGS in evaluateRules.ts for BHAS scoring.
✅ Built
